# P4 · 分镜（整支 MV 里最值钱的一步）

> 分镜写完、给用户看过，再去写代码。**省 Token 全靠这一步**：一支 3 分钟的歌 ≈ 60–90 个镜头，
> 每个镜头渲一次要几分钟；在纸上改分镜 1 分钟，在代码里改分镜 20 分钟。

---

## 1. 9 列分镜表（照抄进 `STORYBOARD.md`）

```markdown
| # | 起–止 | 歌词 | 这句在说什么（人话） | 画面（谁在哪干什么） | 景别/机位 | 情绪·色调 | 卡哪一拍 | 怎么接下一个 |
|---|-------|------|---------------------|---------------------|-----------|-----------|----------|--------------|
| 1 | 0.0–3.2 | —（前奏） | 故事从一个人的深夜开始 | 雪夜街角，路灯亮着，主角从画面左边走进来，雪一直在下 | 中景，慢推向人物 | 冷蓝 + 一点暖黄 | 不卡（前奏） | cut |
| 2 | 3.2–6.4 | 雪落在我肩上 | 他在说自己有多冷，但还在走 | 主角停下，抬手扫肩上的雪，雪更密 | 近景，不动 | 冷蓝，灯变黄一点 | 落在 hits[0] | whip left 0.24s |
```

**一列都不许空。** 空着的那一列，就是你将来要返工的那一镜。

### 各列怎么填

| 列 | 要求 |
|---|---|
| 起–止 | 绝对秒，与前后**首尾相接**。写在 `shots/NN.js` 里要一模一样 |
| 歌词 | 原句；纯画面段写 `—` 并注明段落（前奏/间奏/尾奏） |
| 这句在说什么 | **人话解释**。抽象词必须翻译成具体动作：「自由」→「把窗推开跳出去」；「遗憾」→「手停在半空没敲下去」 |
| 画面 | 谁、在哪、干什么、周围什么在动。**一镜一句话，只一个主要动作** |
| 景别/机位 | 远景/中景/近景/特写 + 机位一种慢动作（推近 ≤8%、横移 ≤10% 画宽、升降 ≤6% 画高） |
| 情绪·色调 | 冷/暖、亮/暗；主色 2 个以内（引擎调色板里挑） |
| 卡哪一拍 | 这个镜头的**换镜时刻**落在 `downbeats` 或 `hits` 的哪一项 |
| 怎么接下一个 | `cut` / `whip` / `lift` / `card` / `flash` / `fade` / `zoom` 之一 + 参数 |

## 2. 时长与节奏（数字，不要凭感觉）

| 段落 | 一镜多长 | 说明 |
|---|---|---|
| 前奏 | 3–6s | 只交代环境，人物可以还没出现 |
| 主歌 | 3–5s | 叙事段，稳 |
| 副歌 | **1.6–2.6s** | 情绪最满，切得最快 |
| 桥段/安静段 | 4–6s | 让观众喘气，画面可以几乎不动 |
| 尾奏 | 3–8s | 最后一个画面要"留住"，别切走 |

- **一镜不超过 8 秒**（超了像 PPT）；**不低于 1.2 秒**（低于此看不清）。
- 全片至少换 **5–6 个不同场景**（同一场景连续 3 镜以上就要换景别或换背景）。
- 「安静一下」的 `events[]`（突然变小声）是最好的转场点：观众耳朵一空，画面切一下最舒服。

## 3. 转场：七种，按画风挑，别全用 fade

| type | 长什么样 | 适合 | 参数 |
|---|---|---|---|
| `cut` | 硬切 | 同一场景内换景别；鼓点最重的地方 | — |
| `whip` | 甩镜：画面横向拖影飞出 | **像素风主用**；副歌快切 | `dir:'left'\|'right'`, `dur:0.2–0.3` |
| `card` | 卡片滑入覆盖：新镜像一张纸片推进来 | **拼贴风主用** | `dir`, `dur:0.28–0.4` |
| `lift` | 旧画面像纸一样被"揭开" | 拼贴/蜡笔，换场景 | `dur:0.3–0.45` |
| `flash` | 白闪/亮闪一瞬 | 重音 `hits`、情绪爆发 | `dur:0.12–0.2` |
| `fade` | 黑场过渡 | **一段只许一次**（段落交界/结尾） | `dur:0.4–0.8` |
| `zoom` | 上一镜快速推近后切 | 悬念/进入回忆 | `dur:0.2–0.35` |

**衔接铁律**：新镜头的**第一帧**，角色的位置/大小/朝向/姿势要能和上一镜的**最后一帧**对上（连续动作），或者**明显不同**（刻意的场景切换）。最难看的是"差不多但又不太一样"——观众会觉得画面跳了一下。

> 教程作者的实测：第一支 MV 20 个镜头里有 12 个要么硬切要么整屏叠化，看着廉价。**写分镜时就把"怎么接"写清楚**，等于提前解决了这个毛病。

## 4. 抽象歌词怎么落地（作者换了三个故事才定稿的那个坑）

拿到一句抽象的歌词，按这个顺序走：

1. **问自己"这句在讲什么情绪"**：孤独 / 释怀 / 不甘 / 心动 / 告别。
2. **给这个情绪配一个具体动作**（不是形容词）：孤独 → 一个人吃两人份的饭；释怀 → 把钥匙放回桌上；不甘 → 手停在门把上没推开。
3. **给这个动作配一个物件**：伞、旧手机、公交车票、一盆快死的绿植。**物件要能贯穿全片**——它第二次出现时观众会有感觉。
4. **给这个物件配一条变化线**：第 1 次出现（完好）→ 第 2 次（破了）→ 第 3 次（放下了）。这就是"故事"。
5. 整支 MV 只需要 **一条主线 + 一个物件 + 三次出现**。不要塞副线。

**自检**：把 9 列表的"这句在说什么"这一列单独读一遍，能不能连成一个故事？连不成 → 用户会看不懂，回去改。

---

## 5. 给用户看分镜（G4 闸门）

用 `ask_user_question` 给 2–4 个选项，别让用户读 90 行表格自己挑毛病：

- 选项 A：故事这样走可以，开做
- 选项 B：主线保留，换个物件（让他说换什么）
- 选项 C：故事重来，我给你三个方向（列出来）
- 选项 D：先只做副歌那 20 秒试试水

一次只问一件事；用户说"都可以"就按 A 走，并在 `REVIEW.md` 记一句"用户授权按此分镜推进"。

## 6. 分镜 → 代码的映射（别在 P5 重新想一遍）

```js
// shots/02.js
SHOTS.push({
  id: 2, start: 3.2, end: 6.4,
  cam: { from:{x:API.cx, y:API.H*0.5, zoom:1.0}, to:{x:API.cx, y:API.H*0.47, zoom:1.05} },
  bg: { kind:'street-night' },
  enter: { type:'whip', dir:'left', dur:0.24 },
  note: '雪落在我肩上：停下扫雪',
  draw(g,u,t,API,cam){
    // 1) 环境里一直在动的东西（雪、灯）
    // 2) 主角：位置/姿势/表情 —— 一个动作
    // 3) 情绪点：u 到 0.5 时抬手
  },
});
```

- `start/end` ← 第 1 列
- `cam` ← 第 6 列（"一种慢动作"）
- `enter` ← 第 9 列
- `bg` ← 第 5 列的"在哪"
- `draw` 里的三段注释 ← 第 5 列那句话

**一镜写完立刻渲图看一眼**（见 `shots.md` 的五步），不要连写三镜。
