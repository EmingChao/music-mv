# P1 · 听歌与歌词时间轴

> 一支 MV 的所有毛病里，**"歌词比声音早/晚 1–2 秒"是最高频、也最丢人的一个**。这一篇专门治它。
> 读完你应该能回答三个问题：这首歌多少 BPM？第一拍在第几秒？每句歌词从第几秒唱到第几秒？

---

## 1. 命令

```bash
./mv.sh analyze song.mp3            # → song-analysis.json（+ 屏幕上的摘要）
./mv.sh analyze song.mp3 --tempo-hint 92    # 测出来差一倍时（常见 70↔140）用它校正
./mv.sh lyric song.lrc -o work/my-mv/lyrics.js   # LRC → lyrics.js（带时间轴，最准）
./mv.sh lyric lyrics.txt -o work/my-mv/lyrics.js # 纯文本：句子会被顺排，**时间轴是估的**
./mv.sh lyric song.srt -o work/my-mv/lyrics.js   # SRT（剪辑软件导出的）也行
```

输入只有视频也行：`./mv.sh analyze mv.mp4` 会自己拆音轨（探一个 MP4 里的音频，别自己 ffmpeg）。

## 2. `song-analysis.json` 里有什么

| 字段 | 意思 | 你怎么用 |
|---|---|---|
| `bpm` / `beat_interval` | 每分钟拍数 / 一拍几秒 | 写 `CFG.BPM`；一拍 = `60/BPM` 秒 |
| `beats[]` | 每一拍的绝对秒 | 卡点用；想看"这一下落在第几拍"直接查表 |
| `downbeats[]` | 每小节第一拍（强拍） | 换镜头优先挑这里 |
| `sections[]` | `{start,end,rel_db,level}` 段落（约 20s 一段，按响度分层） | 情绪曲线、主歌/副歌划分 |
| `events[]` | `{t,type:'up'/'down',change_db}` 突然变响/变安静 | 天然的转场点（**"安静一下"最适合切场景**） |
| `hits[]` | `{t,strength}` 最重的 8 下（间隔≥3s） | 关键画面、闪白、角色情绪爆发点 |
| `last_hit` | 最后一下重音 | 决定结尾镜头什么时候收 |
| `lufs` / `true_peak` | 整曲响度/峰值 | 交付时对 −14 LUFS 的基线 |
| `duration` | 片长（秒） | 写 `CFG.DURATION`，**必须和最后一个镜头的 end 一致** |

> **`CFG.OFF` 是什么**：第一拍出现在音频的第几秒。多数歌 `OFF≈0`，但前奏有自由节奏时第一拍会在 0.3–1.5s。写错 OFF，全片卡点会整体偏移一点点（人耳听得出"差一口气"）。
> 判断方法：把 `OFF` 调成 `downbeats[0]` 附近，渲一帧在 `downbeats[3]` 的画面，看动作是不是正好落在那一下。

## 3. LRC → lyrics.js 的四个坑

1. **`[mm:ss.xx]` 是"这句开始唱"的时间，不是结束时间。** `srt2js.py` 用下一句的起点当本句的终点（并对最后一句补 2 秒）。所以 **LRC 里句与句之间不能有 >3s 的空洞**（间奏），否则会有一句歌词挂在间奏上唱 15 秒。处理：在间奏处手动断句，或删掉那一行的文字只留时间戳。
2. **一句太长要拆。** 超过 14 个汉字，人一眼扫不完全句。`lyrics.js` 里主动拆成两行，时间各分一半。
3. **一行里塞了两句**（`[00:12.00]天黑了 我还在走` 用空格隔开两句）：画面只能演一句，要么拆时间，要么把后半句删掉。
4. **重复副歌**：同一句歌词出现 3 次，`lyrics.js` 里必须有 3 条独立记录（不同时间），不要只写一条然后靠"循环"。

## 4. 没有时间轴怎么办（三种现实情况）

| 情况 | 做法 | 精度 |
|---|---|---|
| 有 LRC / 剪辑软件能导出 SRT | 直接 `./mv.sh lyric` | 准（±0.1s） |
| 只有纯文本歌词 | `./mv.sh lyric lyrics.txt` 顺排 + `lyric_grid.py --bpm <实测> --offset <OFF>` 的节拍网格 | 估的（±1–3s），**必须自己听一遍改** |
| AI 说"歌词有版权不给你转" | ① 剪辑软件（剪映/PR）自动识别字幕 → 导出 SRT ② 音乐 App 里搜歌词复制 → 自己按听感打时间戳 | ① 很准 |

> **豆包总结里提到的踩坑（保留）**：伴奏很重的歌（DJ/电子/说唱）自动识别出来的歌词**会有错别字**，尤其是念白和副歌重复段。导进剪辑软件对着听一遍改字，比渲完再发现错字便宜一百倍。

## 5. 歌词与画面的对齐（这类片子真正的"踩点"）

- **一句歌词 = 一个主要动作**。这句唱"雪落在我肩上"，画面就演"雪落在肩上"，不要同时演走路+回头+叹气。
- 动作的**峰值**要落在这一句的**重音**上：用 `hits[]` 里落在这句区间内的那一响，把动作的顶点对到它（`u` 到 0.5 时正好是那一响）。
- 句与句之间有空隙（>0.6s）→ 画面**停一下**或让镜头本身继续动（雪还在下、灯还在晃），不要立刻切镜。
- **字幕不许压住脸**：`CFG.SAFE_BOTTOM`（默认 0.15）以下才是歌词区，角色眼睛别掉进去。竖屏更要注意：人物中景时脸通常在 0.35–0.5H。

## 6. 字幕合规（发布向）

- 抖音/快手对脏话有审核：`./mv.sh lyric` 之后跑一次打码检查：
  ```bash
  python3 scripts/mask_words.py --help     # 按它的用法传 lyrics.js 或文本
  ```
  词表在 `assets/banned_words_zh.txt`（256 条）。命中了就用「谐音/星号/改字」三种之一，**不要整句删掉**（观众会觉得卡了）。
- 错别字和繁体/简体混排也会被限流：统一简体。

## 7. 完成后自检（30 秒）

```bash
./mv.sh check work/my-mv      # "歌词"那几行应当是 PASS，不是 WARN
```
- [ ] `CFG.BPM` = json 里的 `bpm`；`CFG.OFF` 对得上第一拍
- [ ] `CFG.DURATION` = 最后一句歌词结束 + ≥0.5s 尾巴（不要一句唱完画面就断）
- [ ] 每句 `end > start` 且 ≥0.6s（短于此人读不完）
- [ ] 没有一句超过 16 字
- [ ] 开头 0–首句之间：要么留纯画面（前奏），要么让第一句从 0.3s 后开始
