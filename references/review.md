# 审图与交付（`read_image` 是唯一的验收标准）

> 你的自我评价不可信，"我觉得应该没问题"是最贵的四个字。
> 这里给一套三层审图法和 6 条硬标准，照着打勾就行。

---

## 1. 三层审图法（每镜都走，从便宜到贵）

### 第 1 层：单帧（3 张）
```bash
./mv.sh stills work/my-mv 12.4,13.6,14.8      # 镜头的 20% / 55% / 90%
read_image work/my-mv/out/stills.jpg
```
看四件事：
1. **是不是空的**（有没有主体、有没有环境）
2. **主体尺寸对不对**（中景角色占画面高 20–28%）
3. **有没有穿帮**（道具挡脸、脚没踩地、角色出画、被字幕压住）
4. **工艺在不在**（像素有台阶、拼贴有撕边投影、蜡笔有抖线纸纹）

### 第 2 层：条带（一镜的运动）
```bash
./mv.sh sweep work/my-mv 12.0 15.0           # 每 0.25s 一格拼成一条
read_image work/my-mv/out/sweep.jpg
```
看三件事：动作**方向**对不对、有没有**跳帧**（某一格突然变了位置）、有没有**某段完全不动**。

### 第 3 层：全片接触表（只在成片前看一次）
```bash
python3 scripts/contact_sheet.py --images work/my-mv/out/frames -o work/my-mv/out/sheet.jpg
read_image work/my-mv/out/sheet.jpg
```
（帧太多就先抽稀：`--every 30`，或用 `mv.sh stills` 传一串关键秒数）
看三件事：**整体节奏**（是不是半小时都一样）、**有没有黑帧**、**场景换了几个**。

## 2. 每镜的四问（G5 闸门，写进 REVIEW.md）

```markdown
## 镜头 03（3.2–6.4s）雪落在我肩上
- 图：out/stills-03.jpg（t=3.8/5.0/6.1）
- ① 空不空：不空（雪+灯+人，三层都有东西）
- ② 尺寸：角色 0.24H，占画面高约 24% ✓
- ③ 穿帮：第一张图右钳挡住眼睛 → 已把钳子下移 0.04H
- ④ 接上一镜：上一镜末帧人在 x=0.42W 朝右；这镜从 x=0.43W 起，姿势一致 ✓
- 结论：过
```

**四问答不全 = 没过。** 尤其是第 ④，90% 的"看着怪"都出在镜与镜的接缝。

## 3. 六条过线标准（全片，交付前逐条对）

| # | 标准 | 怎么验 |
|---|---|---|
| 1 | 没有**连续 1 秒以上几乎不动**的段 | `sweep` 看条带；相邻两格几乎一样就是不动 |
| 2 | 切点都在打算的地方 | 对照 `STORYBOARD.md` 的"起–止"，±0.1s |
| 3 | 没有黑帧 | `deliver` 的 `blackdetect` 输出；接触表也能看出 |
| 4 | 每句歌词画面演的就是这句 | 随机抽 5 句，图上找对应动作 |
| 5 | 脸/手/道具没被歌词压住 | 单帧看；`SAFE_BOTTOM` 以下才有字 |
| 6 | 成片响度与母带差 ≤1 dB | `deliver` 打的 LUFS 三方对比 |

再加两条风格专属：
- `pixel`：缩到 200px 宽仍能看出像素格；没有平滑渐变。
- `collage`/`crayon`：每样东西有投影/笔迹；不是"矢量插画换了配色"。

## 4. 看图之后的决策树（别瞎改）

| 图上看到 | 先改这个 | 不要做 |
|---|---|---|
| 空 | 加环境动效（`fx`）+ 一个近景遮挡 | 加更多粒子堆满 |
| 灰、没层次 | 加一层 `glow` 或把地面/天空分成两层 | 整屏调亮度 |
| 脏、看不清主体 | 减元素；给主体加描边/投影 | 加对比度 |
| 太满、眼花 | 砍掉一半装饰 | 缩小所有元素 |
| 假（像矢量插画） | 回 `styles.md` "身份判据" 逐条补工艺 | 加滤镜 |
| 抖/闪 | 查 `Math.random`、种子跟 `t` 变 | 降帧率掩盖 |
| 角色不像"同一只" | 回 `character.js`，对照设定图 | 在镜头里局部微调 |

## 5. 交付命令与判读

```bash
./mv.sh render work/my-mv                     # 后台：run_in_background: true
./mv.sh encode work/my-mv
./mv.sh deliver work/my-mv song.mp3           # 末行必须是 DELIVER PASS
```

`deliver` 会替你打这些，你要会读：

| 输出 | 合格值 | 不合格怎么办 |
|---|---|---|
| `resolution` | 1080x1920 或 1920x1080 | 查 `CFG` 与 `OUT` |
| `r_frame_rate` | 30/1 | `CFG.FPS` 与渲帧的 `--fps` 要一致 |
| `codec_name / profile` | h264 / High | 用 `deliver`，别自己拼 ffmpeg |
| `pix_fmt` | yuv420p | 同上 |
| `bit_rate` | 6–12 Mbps | `-b:v 8M`（`deliver` 已带） |
| `Integrated loudness` | −14 ±1 LUFS | `deliver --target-lufs` 微调 |
| `True peak` | ≤ −1 dBTP | 同上 |
| `blackdetect` | 无输出 | 找黑帧所在秒 → 对应镜头 |
| `duration` | 与歌长差 ≤0.2s | `CFG.DURATION` |

**最后一步**：`present work/my-mv/out/deliver.mp4`，并把接触表缩略图贴给用户（`![](out/sheet.jpg)`）。

---

## 6. 交付话术（给用户看的三行）

1. 一句话：什么风格、多长、多少镜、讲了个什么故事。
2. 一处取舍：例如"副歌第 2 句原本想用长镜，改成 2 个快切，卡鼓点更准"。
3. 一个待定：例如"结尾 3 秒留白，如果你要发抖音建议裁到 2 秒"。

## 7. 返工成本表（决定"改还是重做"）

| 要改的东西 | 代价 | 建议 |
|---|---|---|
| 一句歌词的时间 | 改 `lyrics.js` 一行 | 立刻改 |
| 一个镜头的构图/动作 | 改一个 `shots/NN.js` + 只重渲这段 | 改 |
| 一个镜头的时长 | 改 `start/end`，**相邻镜也要跟着改** | 改，同时跑 `check` |
| 角色长相 | 改 `character.js` → **全片重渲** | 想清楚再动 |
| 画风工艺 | 改 `engine.js` → 全片重渲，且失去基线 | 只在 P2–P3 阶段改 |
| 分镜整体故事 | 重写 `shots/*` | 回 P4，先给用户看新分镜 |
